# Review: mikrotik_router coordinator/API layer (master 8852df1)

Paths relative to custom_components/mikrotik_router. Verified by reading source; librouteros 4.2.2 and mac_vendor_lookup 0.1.15 read from the scratchpad venv.

## HIGH

1. **Deleted/empty data is never propagated; stale entries live forever.** coordinator.py reuses `data=self.ds[...]` for interface, nat, mangle, filter, kid-control, ppp_secret, netwatch, script, queue, dns, dhcp, dhcp-server, dhcp-client, dhcp-network, arp, bridge_host, environment (e.g. 784, 980, 1051, 1901, 1946). parse_api returns `data` unchanged when `source` is falsy (apiparser.py:196-199), and `MikrotikAPI.query` returns `response or None` (mikrotikapi.py:389), so an empty list is indistinguishable from an error. Nothing ever removes keys (only the nat/mangle/filter dedupe at 1126/1218/1328 and arp pop at 1924).
   Scenario: a device leaves ARP. Its entry stays, so `process_interface_client` (1012-1033) reports client-ip "multiple" for the port forever. A deleted DHCP lease keeps overriding the host IP (2304-2315). A deleted NAT rule/queue keeps an "available" entity with last state. The last lease/rule removed is never noticed (empty list -> None).
   Fix: build a fresh dict per poll and carry over only computed fields (rx-previous etc.); distinguish `None` (error) from `[]`.

2. **Transient/optional errors read as "no clients", causing presence flapping.** `self.ds["wireless_hosts"] = {}` is reset in place at 2142 and filled by later network queries in an executor thread, while `MikrotikTrackerCoordinator` (10 s) calls `async_process_host()` on the event loop (coordinator.py:204). If it runs in the window, every wireless host gets `available=False` (2300) and the tracker goes not_home, then home. The same happens when a query returns None (error), since `{}` is then published. Wireless/CAPsMAN hosts use `available` directly (device_tracker.py:366).

3. **Unsynchronised shared `ds` between event loop and executor threads.** `async_process_host` (event loop, called from both coordinators, 668 and 204) iterates and mutates `ds["host"/"dhcp"/"arp"/"wireless_hosts"]` while executor jobs mutate the same dicts in place (`get_arp`, `get_dhcp`, `parse_api` at apiparser.py:218) and executor jobs `process_accounting` (2406) / `process_kid_control_devices` (2563) iterate `ds["host"]` while the loop adds hosts (2173, 2222, 2239). Result: sporadic `RuntimeError: dictionary changed size during iteration`, either failing the tracker update or the whole main poll. In addition `async_process_host` can run twice concurrently across the `await` at 2379 (first vendor-list load/download), and the outer iteration at 2277 then breaks on new keys. Fix: build the new tables in the executor, swap atomically; run host processing from one place only.

4. **Optional-query errors and per-path traps tear down the connection.** `query()` calls `disconnect()` on any TrapError that is not `ignore_trap` (mikrotikapi.py:340, 357, 380) and on every non-Trap exception. `ignore_trap` does not cover `MultiTrapError`, which is not a TrapError subclass in librouteros (exceptions.py: `MultiTrapError(ProtocolError)`). (Upstream PR 517 fixes this part.) Any required path that traps each poll (feature absent, permissions, gps/ups monitor) causes a reconnect per poll, and each reconnect sets `_reconnected` (mikrotikapi.py:209), so the next poll reruns the whole hwinfo block (coordinator.py:602), including the up-to-10 s firmware check. The `disable_health` branch (361) is only reachable for non-Trap exceptions; if RouterOS delivers "no such command prefix" as a trap, CHR/x86 reconnect every poll. Also `disconnect()` sets `_connection_epoch=0` (112), so the very next query reconnects immediately within the same poll; `connected()` is then True at 716 and no UpdateFailed is raised even though earlier queries returned None.

5. **Static DHCP leases get empty interface, then are never pinged.** coordinator.py:2008 compares `arp[uid]["bridge"] != "unknown"` but the default is `""` (1906), so the branch always takes `bridge` -> interface = "" for any lease whose `server` is not a named dhcp-server (e.g. `all`, the default for static leases). async_process_host copies that to host interface (2226); the tracker skips pinging hosts with interface in ["unknown", ""] (coordinator.py:177), so these hosts are never available. Fix: test `!= ""`.

6. **Restored hosts never recovered; registry scanned every poll.** `async_get_host_hass` (576-594) requires `":" in tmp[2]`, but unique ids are `slugify(mac)` = `aa_bb_...` (entity.py:287; checked with homeassistant.util.slugify). Nothing ever matches, `ds["host_hass"]` stays empty, so the whole entity registry is iterated on the event loop every poll (646). Also breaks for router names containing "-" (`split("-")`).

## MEDIUM

7. **`check-for-updates` holds the API lock and may exceed the socket timeout.** coordinator.py:1659 -> `execute()` holds `self.lock` (mikrotikapi.py:435) for the whole streamed command (duration 10). librouteros default socket timeout is 10 s (connect kwargs at mikrotikapi.py:123 never set `timeout`), so a 10 s command can raise socket.timeout -> `disconnect("execute")` (469), losing the connection and the update info. Also blocks first setup by >=10 s and runs again from `get_system_resource` after reboot (1642). Likely related to upstream issue 519 (firmware sensors stale).

8. **Per-interface ethernet monitor calls.** coordinator.py:901-954: one `/interface/ethernet monitor` round trip per ether port per poll (24-port switch = 24 calls); RouterOS accepts comma-separated `.id`/`numbers` in one call. Each call also rebuilds a keymap over all interfaces (`generate_keymap`, apiparser.py:204/268): O(n^2).

9. **TOCTOU / lock misuse in MikrotikAPI.** `connection_check()` is unlocked (80-89): two threads (poll + switch/button) both call `connect()`, leaking one connection and double-setting `_reconnected`. `run_script`, `arp_ping`, `take_client_traffic_snapshot` call `query(return_list=False)` (lock released on return) and then use the lazy Path after re-acquiring; if another thread disconnected/reconnected in between, the stale Path raises and `disconnect()` kills the healthy new connection. `disconnect()` never calls `.close()` on the librouteros Api (none anywhere), and config_flow `validate_input` (config_flow.py:5ff) never closes either.

10. **Presence false negatives from API errors.** `arp_ping` returns False both for "no reply" and for "API down/exception" (mikrotikapi.py:518-556), and the tracker stores that as `available=False` (coordinator.py:190). During a tracker-connection outage (58 s retry back-off) all wired hosts lose `last-seen` refresh. Also one executor job per host, ~0.3 s+ each, serialised (155-196): 60 hosts ~ 20 s+ per cycle; do the loop in one executor job, and return None on API error to keep previous state.

11. **Accounting bugs (RouterOS 6).** (a) `client_traffic` copies address/host-name once at creation (2406-2414, 2563-2575) and keys the per-IP table by that stale address (2421): after a DHCP change traffic is attributed to the old IP's new owner. (b) `_get_accounting_uid_by_ip` uses `is` for string compare (2539) and is O(n^2); hosts sharing "unknown" collapse. (c) 2445 `self.api.query("/ip/accounting")[0].get("threshold")` crashes with TypeError if the query returned None or threshold missing (and re-queries a path already read in `is_accounting_and_local_traffic_enabled`, mikrotikapi.py:566). (d) `_address_part_of_local_network` parses the IP and scans all networks up to 5 times per snapshot entry (2467-2487); precompute once per entry. (e) `IPv4Network(vals["address"])` at 2065 is strict and will raise ValueError on host bits set, failing the poll.

12. **Release-notes request explosion.** update.py:226-240 `decrement_version` walks patch numbers down to `.999` at each minor boundary, so e.g. 7.15 -> 7.20 builds ~5000 version strings and fires ~5000 concurrent GETs to cdn.mikrotik.com via `asyncio.gather` (update.py:128). Needs a bounded list (fetch only real release versions or limit to minor.0..N and stop on 404).

13. **Script sensors stale up to 4 h.** `get_script` is only in the hwinfo block (coordinator.py:617), so last-started/run-count update on reconnect or every 4 h, though they are per-poll sensors.

14. **Uncaught exceptions in update take the whole coordinator down** (generic `Exception` -> all entities unavailable): `get_wireless` master lookup `self.ds["wireless"][master]` KeyError (2129-2131); queue `int()` splits (1852-1894) on any unexpected format; `process_kid_control_devices` arithmetic on "" defaults (2617-2626) if bytes-up/down missing.

15. **Port-traffic rate spike after failed poll.** `interface_traffic_last_run` is advanced even if `/interface` returned None (coordinator.py:835-839); the next good poll divides two intervals of bytes by one interval of time.

16. **mac_vendor_lookup robustness** (mac_vendor_lookup.py 61-114): on first lookup it downloads the whole IEEE OUI list (~6 MB) into `~/.cache`; on download failure `prefixes` stays `{}` so every new host triggers another download attempt, plus sync stat/makedirs/parse on the loop. A truncated cache file makes `load_vendors` raise ValueError forever (swallowed by the `except Exception` at coordinator.py:2381 -> all manufacturers ""). Consider executor-wrapped sync lookup with a bundled/updated file.

17. **Undeclared dependency.** `pytz` is imported (coordinator.py:10, apiparser.py:98) but not in manifest requirements nor HA core's requirements; also `datetime.utcfromtimestamp` (apiparser.py:113, coordinator.py:90) is deprecated. Use `datetime.fromtimestamp(ts, tz=UTC)`.

## LOW

18. apiparser.py:134-137: `from_entry` with a non-empty default coerces booleans through `isinstance(ret, int)` -> `int(True)` = 1, so attributes such as full-duplex/auto-negotiation/sfp-* appear as 1/0.
19. apiparser.py:244: dead condition (`key_primary_found and key not in entry`); an entry whose primary key exists but is empty never falls back to `key_secondary`.
20. get_dhcp calls `get_dhcp_server()` every poll while any lease's server is not a named server (coordinator.py:1996-2001), a rarely-changing table; cache it (4 h block).
21. Duplicate work: `get_system_resource` runs twice in the hwinfo poll (609 and 632); `/ip/accounting` read twice (above); 25+ separate `async_add_executor_job` calls per poll (one job for the whole poll avoids thread hops and between-call lock handoff). `process_interface_client` is O(interfaces x arp) (1012-1033); index ARP by interface once.
22. `get_bridge`, `get_arp`, `get_dhcp` (658-665) run every poll even when host tracking, interface client tracking and client traffic are all off (verify consumers: resource client counters still use them for wireless).
23. Netwatch keyed by `host` (1438) collides for multiple probes of one host; dhcp-network dedupe none.
24. Switches call full `coordinator.async_refresh()` after each toggle (switch.py:93, 106, 181, ...); use `async_request_refresh()` so burst toggles coalesce.
25. update.py:170-183: RouterBoard update entity indexes `current-firmware`/`upgrade-firmware`, which `get_system_routerboard` pops when access is insufficient (coordinator.py:1485) -> KeyError if access changes after entities exist.
26. diagnostics.py: `ds["host_hass"]` values, DNS names, comments, "name" fields are not redacted (names of devices/rules may leak).
27. entity.py `async_update_controller` (listener) re-walks all descriptions x uids on every update of each platform (incl. 10 s tracker coordinator).

No event-loop blocking found for librouteros: every API call goes via `async_add_executor_job` (coordinator.py, config_flow.py, entity.py `async_run_routeros`); `ssl.create_default_context` happens inside `connect()` in an executor. Only blocking-in-loop items: registry scan (6), mac_vendor_lookup file/stat I/O (16).
